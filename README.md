# GENEB — Genomic Embedding Benchmark

GENEB is a multi-task benchmark for DNA sequence encoders: **100 classification tasks** in
**13 functional categories**, evaluated with a **linear probe on precomputed embeddings**
under full-, 10-shot, and 1-shot regimes (reported metrics: MCC, accuracy, macro-F1).

- **GENEB (source):** https://github.com/DeepPavlov/geneb  
- **Leaderboard:** https://huggingface.co/spaces/DeepPavlov/geneb-leaderboard  
- **Task data (pinned):** https://huggingface.co/datasets/DeepPavlov/geneb-tasks  
- **Submit a model:** [CONTRIBUTING.md](CONTRIBUTING.md)

---

## Repository overview

This repository contains three coordinated parts:

1. **Evaluation harness** (`harness/`) — reference code to compute embeddings, train the
   protocol-defined logistic-regression probe, and emit a submission file.
2. **Benchmark definition** (`benchmark/`) — task list, category map, probe settings, and
   model registry metadata.
3. **Leaderboard artifacts** (`leaderboard/`) — static site and JSON tables built from
   reviewed submissions (regenerated by CI; not edited manually).

Official baseline results are stored as `submissions/<model_id>.json`. Model-specific
embedding code is contributed per model (see [CONTRIBUTING.md](CONTRIBUTING.md)); the
repository does not ship weights for third-party encoders.

## Repository layout

```
benchmark/
  benchmark_spec.json       # task list, categories, metrics, probe protocol, dataset pin
  model_meta.json           # display names, parameter counts, links, provenance labels
submissions/
  <model_id>.json           # per-model results (reviewed before merge)
leaderboard/
  index.html                # Hugging Face Space UI
  leaderboard.json          # macro scores by functional category (generated)
  leaderboard_tasks.json    # per-task scores (generated)
  README.md                 # Space metadata
tools/
  validate_submission.py    # schema and completeness checks (CI)
  build_leaderboard.py      # aggregate submissions into leaderboard JSON
  pack_submission.py        # convert legacy per-task JSON logs to submission format
  sync_geneb_dataset.py     # download or publish pinned task CSVs on Hugging Face
model_cards/
  <model_id>.md             # optional training-data and disclosure notes
harness/
  run_GENEB.py              # end-to-end local evaluation → submission JSON
  extractors/
    base.py                 # extractor interface
    <module>.py             # contributor-provided embedding implementation
.github/workflows/
  validate.yml              # PR checks on submissions and spec
  build-and-sync.yml        # rebuild leaderboard and push to the Space (on merge to main)
```

## From submission to leaderboard row

```
extractor + run_GENEB.py  →  submissions/<model_id>.json
        →  PR review + validate.yml
        →  merge  →  build_leaderboard.py  →  leaderboard/*.json  →  Hugging Face Space
```

The canonical sources of truth are `benchmark/benchmark_spec.json`, the pinned dataset
revision in that file, and the reviewed files under `submissions/`. Files under
`leaderboard/` are derived.

## Evaluation and reproducibility

GENEB does **not** provide a central re-scoring service. Each submission is produced
locally with the published harness and data revision; maintainers review pull requests for
schema compliance and plausibility, not by re-running every model.

| Mechanism | Role |
|-----------|------|
| Pinned dataset revision (`benchmark_spec.json`) | Shared train/test partitions |
| Fixed probe protocol (seeds, logistic regression settings) | Comparable downstream evaluation |
| Submission schema + CI validation | Structural completeness and value ranges |
| Extractor code in the PR | Third-party reproduction of reported metrics |
| `meta.provenance` | Distinguishes author-reported vs community-reported runs |
| Model card (recommended) | Training data and contamination disclosure |

Community submissions are labeled `self-reported` in metadata. Reproduction is supported
when the extractor, harness version, and dataset revision are available.
